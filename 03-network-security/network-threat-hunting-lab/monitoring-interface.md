# Monitoring Interface

## Sensor Host

The Ubuntu DMZ server at `192.168.20.10` was used for packet collection and offline Zeek/Suricata analysis.

## Interface Validation

Interface names must be discovered on the active VM rather than copied from another system:

```bash
ip -br address
ip route
```

The correct interface is the one holding the DMZ address and route through `192.168.20.1`. During this lab, the expected VirtualBox-facing interface was validated before capture and sensor deployment.

## Capture Position

Host-based capture on the DMZ server sees traffic delivered to or generated by that server. It is sufficient for the retained USER-to-DMZ scenarios, but it does not provide complete visibility into unrelated switched traffic.

## Capture Command Pattern

```bash
sudo tcpdump -i <DMZ_INTERFACE> -nn -s 0 -w capture.pcap \
  'host 192.168.20.10'
```

Scenario-specific filters were used when focused evidence was required. The final SYN capture intentionally retained TCP control packets only, which explains Zeek's filtered-trace warning.
